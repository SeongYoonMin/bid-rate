# 수집기 추가 절차

## 전제
- 해당 출처는 `inspect-source`로 확인을 마쳤고, 필드 매핑이 `docs/domain.md`에 사용자 확인을 거쳐 적혀 있다. 없으면 멈추고 알린다.
- 민간 사이트 크롤링·로그인 자동화는 만들지 않는다.

## 구조
```
src/lib/collect/<source>/
  fetch.ts      # 원본 가져오기 (API 호출 또는 엑셀 파싱). 원본을 그대로 반환
  toBid.ts      # 원본 1건 → Bid | 변환 실패 사유. 순수 함수
  toBid.test.ts
```

## 단계
1. **`toBid` 먼저 작성:** 순수 함수로, `docs/domain.md`의 매핑만 사용한다.
   - 금액은 원 단위 정수로.
   - 필수 필드가 없거나 공사가 아니면 예외를 던지지 말고 "제외 사유"를 반환한다.
2. **변환 테스트:** `docs/test-cases.md`의 해당 출처 케이스를 `test-writer`로 옮긴다. 실제 응답에서 뽑은 샘플 1~2건을 `fixtures/`에 저장해 사용한다(키·개인정보 제거).
3. **`fetch` 작성:** 
   - API 키는 서버 환경변수에서만 읽는다.
   - 조회 기간 제한이 있으면 나눠서 호출한다 (한전: 최대 90일).
   - 원본 응답을 저장한다.
4. **중복 처리:** 같은 출처 + 공고번호는 한 건으로 합친다(나중 값으로 갱신).
5. **수집 결과 요약을 반환:** 받은 건수, 저장 건수, 제외 건수와 사유별 개수.

## 완료 기준
- 하루치 실제 수집에서 받은 건수 = 저장 건수 + 제외 건수
- 제외 사유가 모두 설명 가능함
