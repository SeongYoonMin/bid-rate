# 데이터 출처 확인 절차

필드 이름과 문서 설명은 틀릴 수 있다. 값을 계산해서 확인한다.
(예: 한전 API `approximateAmount`는 이름과 달리 기초금액과 같은 값이었다.)

## 1. 안전 확인
- 파일에 API 키로 보이는 문자열(40자리 영숫자 등)이 있는지 검색한다. 있으면 출력하지 말고 사용자에게 알린다.
- 원본은 건드리지 않고 `scratch/`에 복사해서 분석한다.

## 2. 개요
- 전체 건수, 공고일 범위, 출처(기관 코드)별 건수
- 공사/용역/물품 구분 필드와 건수 → 이후는 **공사만** 본다
- 낙찰방법(적격심사, 최저가 등)별 건수
- 진행 상태 필드의 값 분포

## 3. 필드별 채움률
공사 건 기준으로 각 필드가 비어 있지 않은 비율. 금액 필드는 특히 확인한다.

## 4. 금액 필드끼리 비교
기초금액 후보 필드 B를 정하고, 다른 금액 필드 X마다:
- X == B 인 건수
- X / B 의 최소·중앙값·최대
- B / X 가 1.1 근처인지 (부가세 관계)

판단 기준:
- X / B 가 공고마다 다르고 0.97~1.03 안 → 예정가격 후보
- 전부 1.0 → 기초금액과 같은 값 (예정가격 아님)
- 비어 있음 → 개찰 전이거나 제공하지 않음

## 5. 개찰 후 반영 여부
입찰 종료일이 충분히 지난 건에서도 상태·금액이 개찰 전 그대로인지 본다.

## 6. 교차 확인 (가능할 때)
예정가격 후보가 있으면 공고번호 2~3건을 골라 사용자에게 전기넷 화면 값과 대조를 요청한다.
API 값: (X/B − 1) × 100 → 전기넷 차트 값과 같아야 한다.
